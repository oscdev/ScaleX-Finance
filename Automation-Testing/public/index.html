How to use this page

Test Personal Loan and Business Loan pipelines: look up rules offline, replay a lead’s disk logs, or run a full end-to-end Live Run against Strapi.

Offline No Strapi · no DB writes

  • Rules & Scoring Reference — formulas, field sources, eligibility & scoring rules.
  • Journey Demo — load a lead’s logs from logs/ (submission → bureau → eligibility → scoring). Eligibility uses the same Show filter as the Live Run report: All lenders, Eligible only, or Failed only.

Online Needs Strapi · writes DB

  • Live Run — creates a real [SUITE-TEST] lead, uploads docs, waits for bureau, runs AI Match, writes an HTML report. No files: one lead from the 25-row default pool. CSV and Documents must be attached together (max 5 rows). The CSV is saved at documents/upload/{product}/live-run.csv; PDFs persist on the lead in Strapi.
  • Requires Strapi (npm run dev in the project root). Check the status pill above.
  1. Live Run: pick product → confirm → Start with no files (one lead from the default 25) or attach CSV and Documents together then Start (max 5). Online only.
  2. Rules & Scoring Reference: pick product → open Lead / Bureau / Eligibility / Scoring docs (offline).
  3. Journey Demo: pick loan type + stage → optional Lead ID → Load (offline). On Eligibility, use Show (All / Eligible only / Failed only) then pick a lender — same grouping as report.html.

Live Run — create lead + full pipeline

Writes DB

Creates real lead(s) and loan application(s) tagged [SUITE-TEST]. Confirm, then Start Live Run. CSV and Documents must be attached together; leave both empty to run one lead from the default pool. Required funnel fields and documents are checked before any POST. Status updates here when the run finishes (async).

  • No files — one unique lead for the selected product, taken from the 25-row pool in documents/default/{product}/sample-default-{product}.csv. Required and optional fields filled. PDFs from the same folder (Personal Loan uses salary_slip.pdf). Each Start rotates to the next row.
  • CSV + Documents — attach both on the same Start (neither alone). 1–5 data rows. CSV cells name files; those PDFs must be in Documents. The CSV is saved at documents/upload/{product}/live-run.csv. PDFs go to Strapi public/uploads/api_uploads/{leadId}-{name}/ (not kept under documents/upload/). Required fields only. More than 5 rows → error, no POST.
  • Sample format beside Documents switches with product. Filenames in the CSV must match attached PDFs (basename only, not a folder path).
  • Confirm checkbox — required; acknowledges DB writes.
  • Start Live Run — background (bureau may take several minutes per lead).

    Tips
    
      
      
        
    • Strapi is required only for Live Run — check the status pill. Rules Reference and Journey Demo work offline.
      • 
        
    • Journey Demo Lead ID must match the selected Loan Type; otherwise the error names the correct product.
      • 
        
    • Eligibility in Journey Demo uses the same Show filter as the Live Run report: All lenders, Eligible only, or Failed only (PASS/FAIL groups).
      • 
        
    • Hard-refresh (Ctrl+Shift+R) after suite updates so app.js / CSS reload.
      • 
        
    • Live Run HTML reports overwrite Automation-Testing/reports/runs/{product}/ (one folder per product).
      • 
        
    • CSV Upload is overwritten at documents/upload/{product}/live-run.csv. PDFs are not kept there — they persist on the lead under public/uploads/api_uploads/{leadId}-{name}/.
      • 
        
    • Set SUITE_ADVISOR_REFERRAL_ID in Automation-Testing/.env if lead create requires an advisor referral.
